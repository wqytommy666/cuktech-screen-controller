# 2026-09-25 连接故障处理记录

## 公共首次部署服务

本次发现旧 Quick Tunnel 域名已返回 NXDOMAIN，但 discovery 仍显示在线。
旧脚本只在启动时检查公网健康；隧道运行中断线时，无法撤下已公布的地址。

修复后由 `ap01_relay_supervisor.py` 持续校验公开 `/health` 的 JSON，失败时
撤下地址，持续失败后重新创建隧道。在线地址带 240 秒有效期并定期续期；
新版客户端拒绝过期记录。健康检查支持系统 HTTPS 代理，避免维护主机的
网络环境导致错误判断。现有客户端仍可通过原 discovery 获取新入口。

部署验证已完成：通过公开 HTTPS 入口申请票据，从小米 OTA CDN 下载
6,804,520 字节的固件，并通过客户端长度、容器头及摘要校验。
这只验证了部署包服务，**没有向 AP01 下发下载或安装指令**。

Quick Tunnel 仍是临时服务：维护电脑关机、休眠或断网时无法提供服务。
长期服务建议迁移到稳定 HTTPS 入口和常在线主机，见
[FDS 服务运维](FDS_RELAY_OPERATOR.zh-CN.md)。

## 已安装 Loader 的屏幕

公共部署服务不参与日常取图。屏幕仍从安装时写入的电脑 IPv4 地址读取
`/screen.gif`。DHCP 改变电脑 IP 后，即使米家在线、Bridge 正常，也可能收不到
画面。应核对安装记录与路由器 DHCP 表，再恢复/保留原地址，不能凭旧日志
宣布屏幕现在已连接，也不能仅凭 ping 失败就占用旧 IP。

本次设备到电脑的测试数据包接收成功，但还没有新的 AP01 取图记录；
旧地址的恢复需要路由器登录后继续处理。本次没有写入设备 Flash。

## Claude 与 Codex 额度

发现 Claude Desktop 官方 `sessionKey` 不存在时，旧代码会在读取 Codex
之前退出，造成两家的面板一起停止更新。

现在分别采集两家额度。一个失败时，其区域显示“未连接”和空值，另一个
继续更新。`/health` 返回 `status: "partial"` 和 `provider_errors`。
若全部失败或数据过期，仍显示完整离线提示。`connected` 指额度采集状态，
不能证明 AP01 已收到图；设备交付仍需近期 `GET /screen.gif 200`。

Mac/Windows 状态文案及 Mac 诊断已相应更新。诊断不再把过期取图日志或
返回 JSON 的离线额度服务显示为全部正常。这里的 App 改动为源码更新，
不代表已发布新的 Mac/Windows 安装包。
