# AP01 固件兼容状态

> 核验日期：2026-09-10。目标型号：`njcuk.enstor.ap01`。

## 结论

| 设备状态 | 当前方案 |
| --- | --- |
| 原厂 `1.0.2_0031` | 支持一次性安装实时 Loader |
| 已安装实时 Loader 的 `1.0.2_0031` | 继续通过局域网刷新 `/tmp`；不要重复 OTA |
| 原厂或已升级 `1.0.2_0041` | 当前不能安装本项目的第三方 Loader |
| `1.0.2_0041` 降级到 `1.0.2_0031` | 已知米家 `miIO.ota` 路径不支持；不要强刷旧 BIN |

如果设备仍为 `1.0.2_0031`，又需要自定义屏幕，请暂时不要在米家中升级
`1.0.2_0041`。已经装好 Loader 的设备，日常图片和额度刷新仍然只写 RAM，
不需要共享中转服务，也不需要再次刷固件。

## 已核验的 `1.0.2_0041`

小米 OTA 服务当前向 AP01 提供：

- 版本：`1.0.2_0041`
- 发布时间：2026-08-13 16:38:14（Asia/Shanghai）
- 大小：6,769,704 字节
- MD5：`3c2d962be82c73860daff903178d9b9e`
- SHA-256：`972db4c136c7ed9e24a83c07c1a7fd62040ca018b08ca285216d26b1fee3c6b9`

官方更新说明包含屏保动画类型、夜间屏幕模式、蜂鸣器开关、本体按键快速
返回及已知问题修复。

对官方 BIN 进行静态对比后，`0041` 新增了明确的 OTA 拒绝分支：当应用固件
请求中的 `signed_file` 为假时，固件记录
`unsigned app firmware rejected for security` 并返回错误。`0031` 的对应路径
会继续处理未签名应用固件。`0041` 同时保留降级禁用检查。

此外，本项目的 Loader 不是通用补丁：

- `0031` 原厂 BIN 为 6,804,520 字节；
- `0041` 的大小、代码布局和函数地址均已变化；
- 当前补丁器会对 `0041` 报 `unexpected firmware size: 6769704` 并停止；
- 即使重新定位全部 Hook，生成的修改版 BIN 仍会在 `0041` 的 OTA 签名入口被
  拒绝。

因此问题不是简单地“更新几个偏移”就能解决。

## FDS 中转与固件签名是两个问题

“无网关：一键获取部署包”负责把经过白名单校验的 `0031` Loader 放到小米 FDS，
再返回短期下载票据。它不能为第三方固件生成酷态科/小米的厂商签名。

- 中转离线：按钮无法取得部署包，但有 FDS 能力的自有网关或恢复后的中转仍可
  传输 `0031` Loader；
- 设备已是 `0041`：即使 FDS 上传成功，设备仍会拒绝未签名 Loader；
- 所以购买网关、换上传 DID 或恢复中转都不能解决 `0041` 的签名限制。

2026-09-10 的本机只读测试已确认：本地 Relay、`0031` Loader 构建、小米 FDS
上传及从官方 OTA CDN 回读校验均正常。当前公开按钮离线发生在 Quick Tunnel
公网入口，和 FDS 上传能力、AP01 固件本身不是同一个故障。

## 应对方案

### 仍在 `0031`

1. 暂停官方固件升级；
2. 首次安装只使用本项目固定哈希的 `0031` Loader；
3. 安装成功后只通过 Bridge 更新图片和额度；
4. 保留电脑固定局域网 IP，并验证 AP01 周期性请求 `GET /screen.gif 200`。

### 已经升级 `0041`

1. 不要把 `0031` BIN 伪装成高版本，不要反复 OTA；
2. 不要把 FDS 票据问题误判成签名问题；
3. 保持使用官方功能，等待以下任一条路径被完整验证：厂商签名的开放接口、
   官方允许降级的包，或独立的硬件恢复/Bootloader 安装路径；
4. 在新的安装路径完成“可恢复、可回读、可验证”之前，不在普通用户设备上试刷。

当前仓库中的 Pogo/UART 研究不等于已经存在可用的 `0041` 降级方案。
